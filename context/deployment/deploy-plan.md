## Prerequisites (verify before Phase 1)

1. [HUMAN] Resources decided to live in tenant `noaignite.com` (private VS subscription).
2. [HUMAN] Azure CLI installed and logged in: `az login` (account `pawel.kunka@noaignite.com`).
3. [HUMAN] GitHub CLI authenticated: `gh auth login` (access to the repo that will hold Flowerpot).

5. [HUMAN] Repo pushed to a GitHub remote (SWA's GitHub integration needs a remote repo). Note: repo currently local-only — a remote must exist first.

## Phase 0 — Push repo to GitHub  [HUMAN + AGENT]

The SWA "GitHub" creation flow links to a remote repo, so the repo must be on GitHub first.

1. [HUMAN] Create the GitHub repo (private or public): `gh repo create Flowerpot --private --source . --remote origin` (run from repo root) — or create in the UI and add the remote.
2. [AGENT] Confirm remote and branch: `git remote -v` and `git --no-pager branch` (expect `main`).
3. [HUMAN] Push: `git push -u origin main`.
4. [GATE] Confirm the repo is visible on GitHub with the full monorepo (frontend/api/shared).

## Phase 1 — Select the correct subscription  [HUMAN]

Risk #1 in the register is deploying into the wrong subscription inside the corporate tenant.

1. [HUMAN] `az login` → pick account `pawel.kunka@noaignite.com`.
2. [HUMAN] List subscriptions: `az account list --output table` and identify the **private Visual Studio** subscription.
3. [HUMAN] Set it active: `az account set --subscription "<VS subscription id>"`.
4. [HUMAN] Confirm: `az account show --output table` — verify name + id are the private VS subscription, not any corporate prod.
5. [GATE] Human confirms the active subscription id out loud / in writing before any resource is created.

## Phase 2 — Provision the resource group + Static Web App via Bicep  [HUMAN + AGENT]

Infra is code, not clicks. `infra/main.bicep` provisions only the SWA (Free, West Europe) for M1L5.

1. [HUMAN] Create the resource group: `az group create --name 10x-flowerpot-group --location westeurope`.
2. [AGENT] Author `infra/main.bicep` (resource `Microsoft.Web/staticSites`, name `10x-flowerpot-swa`, sku `Free`, location `westeurope`) with parameters for name/region.
3. [AGENT] Preview changes read-only: `az deployment group what-if --resource-group 10x-flowerpot-group --template-file infra/main.bicep`.
4. [GATE] Human reviews the what-if output and confirms names before apply.
5. [HUMAN] Apply: `az deployment group create --resource-group 10x-flowerpot-group --template-file infra/main.bicep`.
6. [AGENT] Verify: `az staticwebapp show --name 10x-flowerpot-swa --resource-group 10x-flowerpot-group --output table`.

## Phase 3 — Wire the deploy token into GitHub  [HUMAN]  — DONE

Bicep-provisioned SWA is not GitHub-linked, so the token is wired manually (one-time).

1. [HUMAN] Retrieve the deployment token: `az staticwebapp secrets list --name 10x-flowerpot-swa --resource-group 10x-flowerpot-group --query "properties.apiKey" -o tsv`.
2. [HUMAN] Stored as repo secret **`AZURE_STATIC_WEB_APP_API_KEY`** (repo-scoped). Never echo it into a committed file or log.
3. [GATE] Confirmed the secret exists (`gh secret list`).

## Phase 4 — Author the GitHub Actions deploy workflow  [AGENT]  — DONE

Hand-authored at `.github/workflows/deploy.yml` (not portal-generated), triggered on push to `main` + `workflow_dispatch`. Strategy driven by the npm-workspaces constraint:

1. **Build at repo root** (`npm ci` + `npm run build`) so `@flowerpot/shared` (workspace-only, unpublished) resolves. Per-folder Oryx build would fail on it — hence `skip_app_build` + `skip_api_build`.
2. **Frontend**: deploy pre-built `frontend/dist` (`app_location: frontend/dist`, `skip_app_build: true`).
3. **API**: assemble self-contained `api-dist/` (compiled `dist` + `host.json` + a manifest with `@flowerpot/shared` dropped — it is type-only and erased at compile — then `npm install --omit=dev` pulls only `@azure/functions`). Deploy with `api_location: api-dist`, `skip_api_build: true`.
4. Secret consumed: `${{ secrets.AZURE_STATIC_WEB_APP_API_KEY }}`. `api-dist/` is gitignored (CI artifact).

Validated locally: root build green; API package assembles and installs `@azure/functions`.

## Phase 5 — First deploy + verify  [AGENT + HUMAN]

1. [HUMAN] Merge to `main` (or push) to trigger the deploy Action.
2. [AGENT] Watch the run: `gh run watch` / `gh run view <id> --log`.
3. [AGENT] On success, get the URL: `az staticwebapp show --name 10x-flowerpot-swa --resource-group 10x-flowerpot-group --query "defaultHostname" -o tsv`.
4. [AGENT] Verify frontend: fetch `https://<hostname>/` returns the SPA.
5. [AGENT] Verify API: fetch `https://<hostname>/api/health` returns the `HealthResponse` payload.
6. [GATE] Human confirms the public URL works end to end.
